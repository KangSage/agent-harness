# v0.2 PR7: classifier / workflow engine 재검토 노트

> 이 노트는 classifier 또는 workflow-engine 개념을 계속 보류할지 검토하는 내부 설계 기록이다. automatic classifier, workflow engine, approval system, executable gate semantics를 추가하지 않는다.

## 결론

PR7 결론: automatic risk classifier와 workflow engine은 계속 deferred로 둔다.

현재 repo에는 실제 프로젝트 적용 사례 3회 이상, 반복 수작업 병목, schema/fixture/rendered example 안정성이 모두 입증된 artifact가 없다. 따라서 제품 기능이나 실행 엔진을 만들 근거가 부족하다.

limited preset-assist는 prompt-authoring recommendation 후보일 뿐 automatic classifier나 workflow engine이 아니다. 향후 helper가 생기더라도 preset 추천, 추천 근거, confidence, high-risk trigger 목록, 사람이 확인해야 할 질문까지만 허용한다.

## Burn-down Loop 결과

| Loop | 질문 | 확인 결과 | 결정 |
| --- | --- | --- | --- |
| 1. 근거 수집 | 실제 사용 사례 3회 이상과 반복 병목이 repo artifact로 남아 있는가? | 현재 repo에는 검증 가능한 적용 사례 3회 이상이 없다. | 구현 근거 부족 |
| 2. 위험 모델링 | classifier나 engine이 safety boundary를 넘을 수 있는가? | high-risk downgrade, gate pass as approval, accepted-risk semantic smuggling, legal/compliance conclusion, production execution 위험이 남아 있다. | 자동화 금지 유지 |
| 3. 허용 범위 결정 | 무엇을 future 후보로 남길 수 있는가? | preset recommendation, rationale, confidence, high-risk trigger list, human question list까지만 안전 후보로 볼 수 있다. | prompt-authoring assist 후보만 유지 |
| 4. 문서/검증 반영 | 결론이 조용히 사라지지 않게 할 수 있는가? | follow-up plan과 validator phrase guard로 boundary를 고정한다. | 문서 + validation guard |
| 5. 최종 리뷰 | 전문가 패널이 구현 보류 결론에 동의하는가? | Product/IA, QA, Safety/Risk 관점 모두 docs/contract-only review를 권고했다. | PR7은 research/design note only |

## 명시적 금지

- classifier가 clear high-risk trigger를 `standard`나 `light`로 downgrade한다.
- classifier, AI, validator, workflow engine이 risk를 accept한다.
- workflow engine이 decision gate를 pass하거나 approval로 해석한다.
- workflow engine이 implementation, deployment, production-operation, customer communication, legal/compliance approval을 실행하거나 승인한다.
- legal/compliance 결론, compliant 판단, 고지 의무 판단, policy approval을 자동화한다.
- 운영 DB/API/cloud console/secret store/admin dashboard 접근이나 production remediation을 실행한다.

## 향후 허용 가능한 후보

아래는 기능 약속이 아니라 다음 재검토 때 볼 수 있는 후보 범위다.

- Recommended preset: `light`, `standard`, `high_risk`
- Rationale: 어떤 trigger 때문에 추천했는지
- Confidence: `high`, `medium`, `low`
- High-risk trigger list: auth, permission, privacy, production data, payment, customer impact, legal/compliance review trigger, support operations, rollout, rollback
- Human question list: confidence가 낮거나 high-risk boundary가 불명확할 때 사람에게 물어야 할 질문

권장 문구:

```text
Recommended preset: `high_risk` because these high-risk triggers are present: production data, customer impact, support operations.
Confidence: medium. Ask the listed human question before choosing.
This is a prompt-authoring recommendation, not approval, legal advice, risk acceptance, production readiness, or permission to execute.
```

## 필요한 추가 근거

다음 조건이 충족되기 전에는 classifier나 workflow engine을 만들지 않는다.

- 실제 프로젝트 적용 사례가 3회 이상 repo에 public-safe artifact로 축적된다.
- 사람이 반복해서 같은 preset 선택, gate 작성, accepted-risk 구조화를 수작업으로 하고 있다는 병목이 확인된다.
- high-risk downgrade를 막는 semantic policy gate가 생긴다.
- gate pass를 approval로 해석하는 입력을 막는 negative fixture가 생긴다.
- accepted-risk `basis`나 `approval_evidence` 안의 AI/workflow acceptance smuggling을 막는 policy가 생긴다.
- legal/compliance conclusion과 production-operation execution을 막는 검증이 생긴다.

## 다음 액션

PR7 이후 바로 classifier나 workflow engine을 만들지 않는다. 다음 단계는 실제 prompt-builder 사용 사례를 public-safe 형태로 축적하는 것이다. 사례가 3회 이상 쌓이면 preset-assist를 다시 검토하되, workflow engine과 approval semantics는 계속 별도 검토 대상으로 둔다.
