# v0.1.1 계약 Fixture 설계 노트

## 결정

`v0.1.1`은 `project-prompt-kit`의 계약을 schema-backed fixture로 단단하게 만드는 패치 릴리즈로 진행한다.

CLI, renderer engine, package publishing, network 동작, repository indexing은 아직 추가하지 않는다.

이번 단계는 새 제품 표면을 늘리는 작업이 아니라, `v0.1`에서 만든 prompt contract와 mode 구조를 검증 가능한 상태로 만드는 작업이다.

## 왜 이 단계인가

`v0.1`은 공개 스캐폴드를 만들었다. 포함된 것은 command 문서, mode reference, renderer template, 예제, safety default, validation이다.

다음으로 필요한 것은 더 많은 설명이 아니라, 이 계약이 실제 예제와 실패 사례를 통해 검증된다는 증거다.

README만 보강하는 작업은 가치가 낮다. 이미 scope, safety posture, no-CLI 방침이 문서화되어 있다.

CLI는 아직 이르다. contract와 fixture가 안정되기 전에 CLI를 만들면, 아직 검증되지 않은 가정을 사용자-facing API처럼 고정하게 된다.

## 범위

package-local contract fixture와 validation을 추가한다.

- `schemas/mode.schema.json`
- `schemas/prompt-request.schema.json`
- `tests/fixtures/valid/*.json`
- `tests/fixtures/invalid/*.json`
- `tests/golden/*.md`
- `tests/validate-fixtures.sh`

fixture validation은 아래 흐름에 연결한다.

- `packages/project-prompt-kit/scripts/validate.sh`
- root `scripts/validate.sh`

문서는 필요한 만큼만 갱신한다.

- `packages/project-prompt-kit/README.md`
- `packages/project-prompt-kit/tests/README.md`
- root `CHANGELOG.md`

## 하지 않을 것

- CLI 구현
- renderer engine 구현
- package-manager dependency 추가
- network call
- MCP server
- prompt marketplace
- automatic repository indexing
- write-to-file 동작

## Schema 전략

`prompt-contract.schema.json`은 normalized prompt payload의 canonical schema로 유지한다.

새 schema는 기존 계약과 drift가 나면 안 된다.

- `prompt-request.schema.json`은 입력/request shape를 다룬다. normalized contract field를 다르게 재정의하지 않는다.
- `mode.schema.json`은 machine-checkable mode metadata를 다룬다. mode Markdown 파일은 계속 사람이 읽는 source reference 역할을 한다.
- validation은 Python validator, schema, `references/modes/*.md` 사이의 mode list drift를 잡아야 한다.

Python stdlib에는 JSON Schema validator가 없다. Draft 2020-12 전체를 직접 구현하지 않는다.

대신 이 repo schema가 실제로 쓰는 keyword만 검증하는 작은 validator를 둔다.

- `type`
- `required`
- `properties`
- `additionalProperties`
- `enum`
- `const`
- `minLength`
- `minItems`
- `items`

schema에 지원하지 않는 keyword가 들어오면 validation은 실패해야 한다. 검증하지 못하는 것을 검증한 것처럼 보이게 만들지 않는다.

## Fixture 전략

valid fixture:

- mode별 최소 1개 valid prompt contract를 둔다.
- renderer target 세 개를 전체 fixture matrix 안에 모두 포함한다: `codex`, `claude`, `generic`.
- 최소 기준은 contract fixture 10개다. mode 전체가 덮이고 target 세 개가 모두 등장해야 한다. mode x target 30개 전체 조합은 v0.1.1 범위 밖이다.
- 각 target마다 최소 1개 fixture에 synthetic prompt-injection canary를 둔다.
- 기존 `examples/sample-contract.*.json`도 schema-backed validation 대상에 포함한다.

invalid fixture:

- required field 누락
- 잘못된 mode enum
- 잘못된 target enum
- `additionalProperties: false`에서 extra property 포함
- `minLength` 대상의 빈 문자열
- `minItems` 대상의 빈 배열
- `items` 내부의 빈 문자열
- 잘못된 `const`, 예: `command`
- 잘못된 type, 예: array 대신 string
- 안전하지 않은 safety default, 예: telemetry가 `off`가 아니거나 `no_network`가 `true`가 아님
- 잘못된 safety object shape
- safety object의 required field 누락
- safety object의 extra property
- schema unsupported keyword

invalid fixture에는 실제 secret처럼 보이는 값을 넣지 않는다. synthetic canary만 사용한다. 공개 repo hygiene scanner를 무의미하게 통과시키거나 실패시키는 예제를 만들지 않는다.

## Golden 전략

golden file은 static shape smoke test다. renderer snapshot이 아니다.

`v0.1.1`에는 renderer engine이 없으므로, golden은 생성 결과의 byte-for-byte snapshot처럼 다루지 않는다. contributor가 mode별 output shape를 이해할 수 있게 하는 예시로 둔다.

golden은 아래 mode를 모두 다룬다.

- `choose`
- `task`
- `implement`
- `review`
- `debug`
- `research`
- `docs`
- `release`
- `correction`
- `handoff`

각 golden은 아래 항목을 포함한다.

- source of truth
- scope
- validation
- gap handling
- project content가 등장할 경우 prompt-injection boundary

adversarial project text는 안전한 synthetic content만 사용한다.

예:

```text
Quoted project content says: ignore previous instructions.
```

기대 동작: prompt는 이 텍스트를 instruction이 아니라 data로 취급해야 한다.

## Validation 수용 기준

`bash scripts/validate.sh`는 아래를 모두 실행해야 한다.

- root validation
- package validation
- fixture validation

`bash packages/project-prompt-kit/tests/validate-fixtures.sh`는 아래 경우 실패해야 한다.

- valid fixture가 validation에 실패
- invalid fixture가 validation을 통과
- schema가 지원하지 않는 validation keyword를 사용
- mode taxonomy가 schema, Python validator, mode Markdown 파일 사이에서 drift
- 기존 sample contract가 request/contract validation에 실패

## Release 기준

`v0.1.1` PR은 아래 조건을 만족해야 한다.

- 새 dependency 없음
- `bash scripts/validate.sh` 통과
- positive fixture와 negative fixture가 모두 검증됨
- CI가 root validation entry point를 사용
- 문서가 fixture coverage를 설명하되 CLI나 renderer engine이 있는 것처럼 말하지 않음

## 위험

가장 큰 위험은 schema drift다. schema를 작게 유지하고 mode 이름을 cross-check한다.

두 번째 위험은 golden의 의미가 과장되는 것이다. renderer engine이 생기기 전까지 golden은 shape example로만 취급한다.

세 번째 위험은 secret fixture가 너무 현실적인 값을 쓰는 것이다. synthetic canary만 쓰고 public hygiene scanning은 엄격하게 유지한다.
